# Testing with Clerk & TestSprite

This project uses **Clerk** for authentication, which requires specific configuration for End-to-End (E2E) testing.

## Prerequisites

Ensure your `.env` or `.env.local` contains the following keys (retrieved from your Clerk Dashboard):

```bash
CLERK_SECRET_KEY=sk_test_...
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
```

## Running Tests

We use **Playwright** for E2E testing. The configuration has been updated to use `@clerk/testing` for handling authentication.

```bash
pnpm test:e2e
```

## TestSprite Integration

TestSprite (or any automated agent) should follow these patterns when generating tests:

1.  **Authentication**: Do NOT try to fill out the login form at `/login`. Instead, use the `setupClerkTestingToken` helper to bypass authentication.

    ```typescript
    import { setupClerkTestingToken } from "@clerk/testing/playwright";

    test.beforeEach(async ({ page }) => {
      await setupClerkTestingToken({ page });
    });
    ```

2.  **Database Seeding**:
    - Tests requiring specific user roles (e.g., Admin) or data (e.g., Business Profiles) currently face a limitation: we cannot easily seed data for the "random" test user generated by the Clerk token.
    - **Workaround**: Use a fixed set of credentials in CI, or update the tests to handle empty states gracefully.

3.  **Selectors**:
    - When testing the UI, prefer `role` selectors (e.g., `getByRole('button', { name: '...' })`) over CSS classes, as Clerk components are opaque.
