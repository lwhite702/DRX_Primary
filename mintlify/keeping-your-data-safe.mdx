# Keeping your data safe

This page is the operator security runbook for account access and customer data handling.

## What this page is for

Use this guide to keep account access tight, reduce avoidable data exposure, and respond quickly when a session or login pattern looks wrong.

This guide is written for day-to-day operators and managers, not only technical admins.

## Before you start

- **Recommended role**:
  - Manager for routine checks
  - Owner/super admin for high-impact actions
- **Routes and controls used**:
  - `/settings`
  - `/settings/team`
  - Session routes under security APIs
  - Privacy controls in settings
- **Core rule**:
  - Shared accounts create hidden risk. Use named accounts and role limits.

## Fast path

1. **Review role assignments** in `/settings/team`.
   - Remove extra access first.
2. **Review privacy controls** in `/settings`.
   - Confirm field visibility and masking mode match your store policy.
   - Confirm retention behavior for temporary profiles.
3. **Check vault status in settings**.
   - Confirm key state indicators are healthy.
4. **Review active sessions**.
   - Identify unknown device/session entries.
   - Revoke sessions that do not match known operator use.
5. **Handle failed login patterns**.
   - Watch lockout events and reset workflow for affected user.
6. **Set weekly review habit**.
   - Roles, sessions, and data-footprint checks should be part of manager routine.

## If blocked

- **Cannot revoke session**:
  - Current role likely lacks required scope.
  - Escalate to owner/super admin.
- **Vault status shows missing key state**:
  - Do not ignore this.
  - Pause sensitive customer edits and escalate immediately.
- **Repeated lockout events for one account**:
  - Treat as possible credential issue.
  - Rotate password, revoke sessions, and re-check role rights.
- **Masked fields confuse cashier flow**:
  - Verify screen mode setting and manual mask preference.
  - Do not disable masking globally without manager review.

## Weekly safety routine

1. Review active sessions and revoke unknown devices.
2. Review role changes and remove stale elevated access.
3. Check privacy profile and masking settings still match store policy.
4. Confirm temporary profile retention is still set to intended window.

## Incident response quick card

- If account risk is suspected: revoke sessions, rotate credentials, and review logs.
- If vault/key state looks wrong: pause sensitive edits and escalate.
- If lockout repeats: treat as high-priority account event and document actions.

## Manager review questions

Ask these each week:

- Which accounts had elevated access this week and why?
- Were unknown sessions revoked the same day they were found?
- Did masking settings stay in the intended mode during staffed hours?
- Were there lockout events that suggest shared credentials or weak handoff habits?
