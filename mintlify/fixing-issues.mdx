This page is the incident playbook for frontline operators.

## What this page is for

Use this guide when a live flow breaks and you need fast, repeatable steps to recover without creating extra data problems.

The goal is simple: restore flow, keep records clean, and escalate with useful details.

## Before you start

- **Recommended role**: Any operator can run first checks; manager handles deeper escalations.
- **Routes often involved**:
  - `/pos/sale`
  - `/sales`
  - `/inventory`
  - `/customers`
  - `/insights`
  - `/help`
- **Escalation channel**:
  - Use in-app issue reporting and include route + exact action + exact error text.

## Fast path

1. **Stop and identify route**.
   - Name exact route and last click.
2. **Retry once only**.
   - Do not spam submit actions.
3. **Confirm whether action already completed**.
   - For checkout issues, check sale ID and history first.
4. **Apply route-specific checks** (below).
5. **Escalate with full context** if unresolved.

## If blocked

### POS / Quick Sale issues

- **Symptom**: Cannot complete sale
- **Checks**:
  - Cart has items
  - Payment method selected
  - Credit has attached customer and eligibility
  - Stock not zero
- **Recovery**:
  - Retry once.
  - Verify no sale ID was already created before re-submitting.

### Inventory issues

- **Symptom**: Stock mismatch or intake failure
- **Checks**:
  - Correct product selected
  - Intake values valid
  - Approval-required path acknowledged
- **Recovery**:
  - Avoid duplicate intake submissions.
  - Use adjustment with clear reason after recount.

### Customer issues

- **Symptom**: Customer save/attach fails
- **Checks**:
  - Alias-only payload works as fallback
  - No malformed fields
  - Correct business context
- **Recovery**:
  - Save minimal profile first, then enrich fields.

### Metrics/report issues

- **Symptom**: Totals look wrong
- **Checks**:
  - Date scope and business context
  - Transaction completion status
- **Recovery**:
  - Cross-check with sale records before reporting as system bug.

### Access issues

- **Symptom**: Page visible but action denied
- **Checks**:
  - Role permissions for action
  - Team role assignment current
- **Recovery**:
  - Escalate to manager/owner for role correction.

## Escalation payload template

When opening an issue, include:

- Route path
- Last click/action
- Exact error text
- Whether sale ID appeared
- Whether retry changed behavior
- Staff role used during issue

## Do-not-do list during incidents

- Do not retry checkout repeatedly without status check.
- Do not run manual stock edits to hide unresolved intake issues.
- Do not change team roles during lane pressure unless it is required for recovery.
