# Failsafe and self-destruct

This page explains what safeguards are real in DRX and what is not a normal operator feature.

## What this page is for

Use this guide when a team member asks for a "panic wipe" or assumes the app has one-click destructive controls.

This page prevents dangerous mistakes by separating live safeguards from unsupported assumptions.

## Before you start

- **Recommended role**: Manager or owner for any destructive request review.
- **Routes involved**:
  - `/help`
  - `/inventory/audit`
  - session and account admin routes
- **Ground rule**:
  - Do not run destructive account actions during lane pressure without owner review.

## Fast path

1. **Confirm incident type**.
   - Data error, account risk, device loss, or legal request.
2. **Pause risky actions**.
   - Stop manual overrides until issue is understood.
3. **Use live safeguards**.
   - Session revoke for account concerns.
   - Audit review for stock/sale disputes.
   - Support escalation for route failures.
4. **Escalate destructive requests**.
   - Owner/super admin decides if deletion path is required.
5. **Document action and outcome**.
   - Keep a clear trail for handoff.

## If blocked

- **Team asks for full workspace destruction button**:
  - That is not a normal operator feature.
  - Use controlled admin/legal process.
- **Assumption that offline queue means full rollback**:
  - Offline queue helps continuity but does not replace careful incident handling.
- **Unclear whether user deletion is appropriate**:
  - Pause and escalate before action.
  - Confirm legal and business policy path.

## What is beta here

- Core safeguard behavior listed here is live.
- Some broader incident analytics views are beta-limited and should not replace route-level checks.
