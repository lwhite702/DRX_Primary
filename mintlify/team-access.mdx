# Team access

This page explains how DRX role access works in daily operations.

## What this page is for

Use this guide to assign roles, verify action boundaries, and reduce avoidable mistakes caused by over-permissioned accounts.

Team access is managed from **Settings -> Manage Team** and the **Team Management** route.

## Before you start

- **Recommended role**: Owner, super admin, or manager with user-management scope.
- **Primary route**: `/settings/team`
- **Reference route**: `/settings`
- **Policy prep**:
  - Decide who should be cashier, supervisor, manager.
  - Decide who can approve sensitive actions on live shift.

## Fast path

1. **Open Team Management** (`/settings/team`).
2. **Review current members and roles**.
3. **Assign least-needed role first**.
   - Start low, then expand only if workflow requires it.
4. **Save and verify live behavior**.
   - Log in as that role and test one allowed action and one blocked action.
5. **Document role changes** in your shift handoff notes.

## Role-task matrix (live behavior)

| Task | Cashier | Supervisor | Manager | Owner / Super admin |
| --- | --- | --- | --- | --- |
| Create sale | Yes | Yes | Yes | Yes |
| Process payment | Yes | Yes | Yes | Yes |
| Void/discount sensitive actions | No | Yes | Yes | Yes |
| Manage customers | View only | Yes | Yes | Yes |
| Manage inventory levels | No | No | Yes | Yes |
| Change store settings | No | No | Yes | Yes |
| Manage staff roles | No | No | Yes | Yes |
| System-level controls | No | No | No | Yes |

## If blocked

- **Team page opens but role change controls are disabled**:
  - Current account likely lacks user-management scope.
- **User can view a page but action fails**:
  - This is expected when route visibility and action rights differ.
- **Owner role cannot be reassigned in normal flow**:
  - Expected safeguard. Use approved admin path only.
- **Live workflow broke after role downgrade**:
  - Re-run role-task check and restore only missing rights.

## What is beta here

- Core role assignment and route/action checks are live.
- Some cross-business admin surfaces are beta-limited and should not be your day-to-day role management path.

## Weekly role hygiene check

- Remove elevated access for staff who changed duties.
- Confirm supervisor and manager counts match current staffing.
- Verify at least one denied-action test for each role still behaves correctly.

## Handoff rule

When roles change, include this in shift handoff:

- User ID changed
- Old role -> new role
- Why it changed
- Which route/action was validated after change
