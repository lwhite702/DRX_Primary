# Beta access and use

DRX runs active beta surfaces alongside stable live routes. This page tells operators how to work safely when a beta surface is involved.

## What beta means in operator workflow

- A beta surface can be present but limited.
- Labels and layout can change between releases.
- Team process should assume guardrails are still tightening in those areas.

## What this means for shift operations

1. Keep core lane workflow on stable routes first.
2. Treat minimal pages as expected if listed as beta.
3. Keep a manual fallback for any non-critical beta surface.
4. Report route mismatches with exact reproduction steps.

## Beta behavior rules for staff

- Verify totals before final submit on any changed flow.
- Do not train all staff on a fresh beta behavior in one shot.
- Start with one lane or one manager-led shift.
- Capture route + click path + error text when reporting issues.

## Current beta-limited areas to watch

- Reports depth remains limited in current state.
- Some multi-business control surfaces are still evolving.
- Extended export/report packaging in several areas may be partial.

## What is live and stable right now

- Quick Sale path (`/pos/sale`, `/pos/payment`, `/pos/complete`)
- Standard sales route (`/sales`)
- Inventory core routes (`/inventory`, `/inventory/intake`, `/inventory/adjust`, `/inventory/audit`)
- Customer core routes (`/customers`, `/customers/[id]`)
- Team access and settings core routes
